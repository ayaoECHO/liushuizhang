# 关于与配置

## 一、功能说明

第四个 tab，包含：

1. **产品介绍**：个人时间管理工具，四象限管优先级、AI 自然语言记录时间、质量分析回顾
2. **功能说明**：四个核心功能的简要介绍
3. **API Key 配置**：用户自配 DeepSeek API key（在 "阿药" tab 中或通过设置入口）
4. **联系方式**：阿药的电话和微信

## 二、技术原理

### API Key 管理

API key 不放在前端 localStorage，而是加密存储在服务端：

```
用户输入 API key
  → PUT /api/auth/apikey { apiKey: "sk-xxx" }
    → encrypt(apiKey) → AES-256-CBC 加密
    → 存入 profile.json 的 apiKey 字段
  → 后续 AI 调用时：从 profile 读 → decrypt → 使用

用户删除 API key
  → DELETE /api/auth/apikey
    → profile.apiKey = null
    → 保存 profile
```

加密格式：`iv:encrypted_text`（16 字节随机 IV + AES-256-CBC 密文，hex 编码）。

### 前端状态

```javascript
state = {
  token: JWT token,
  hasApiKey: boolean,  // 是否有有效的 API key
  // ...
}
```

`hasApiKey` 决定 AI 相关功能是否可用（对话/总结/评分/日记/报告）。未配置 API key 时，AI 功能入口显示提示。

## 五、修改注意事项

1. **密钥存在 profile.json**：不在 `.env` 文件里。每个用户独立加密存储。删用户目录则密钥丢失。

2. **加密密钥来源**：`ENCRYPTION_KEY` 从 `.env` 文件读取，默认值 `dev_encryption_key_32b`。生产环境必须改。

3. **API key 以明文传输**：前端 → 后端走 HTTPS（如果部署在生产），但本地开发是 HTTP。如果需要更高安全性，可以考虑前端做一次 hash。

4. **hasApiKey 由后端返回**：`GET /api/auth/me` 返回 `{ name, hasApiKey }`。前端不能自己判断 key 是否存在。
