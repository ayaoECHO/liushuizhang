# 本周周报（原始日记总结）

## 一、功能说明

洞察页的「周报」按钮，AI 总结**指定周**的原始日记、生成周报。周报区支持**选周 + 查看历史周报**：

- 默认显示本周（周一~周日）周报
- 可输入日期「定位到该周」，或用「◀ 上周 / 本周 / 下周 ▶」切换周
- 下拉框「历史周报」列出所有已有周报的周，点击直接查看
- 该周无周报时显示「生成该周周报」按钮，点击为所选周生成
- 已有周报显示「重新生成」，可覆盖

点「周报」后，AI 读取该周（周一~周日）每天的原始日记，输出周报，包含两部分：

**工作**：按天清单，一眼看清每天做了什么。

```
周一：上下文库项目同步的看板和会议同步
周二：看27年教务交付手册发现缺乏学员视角，整理开展思路
周三：写完学员视角的交付方案（html 形态）
周四：上午开会，下午做元内容输出测试，重写了几篇
周五：上午开会，下午梳理元内容项目进度和执行方案
```

**生活**：一眼看清本周身体、精神各花了多少时间，精神领域主要在做什么。

```
身体：共约 12 小时（睡眠 42h、通勤 4h、吃饭 3h、洗澡 1h…）
精神：共约 8 小时（看小说 5h、刷视频 1h…）
```

周报生成后保存到后端 `weekly_reports.json`。下次进入洞察页直接显示当前周已保存的周报。

## 二、技术原理

### 1. 数据流

```
用户定位到某周（默认本周 / 输入日期 / 上周本周下周 / 下拉历史周）
  → weeklyMonday = 该周周一
  → renderWeeklyReport(monday)
    → weeklyReports[monday] 有 → 直接显示
    → 无 → 显示「生成该周周报」（未来周不显示）

点「生成该周周报」/「重新生成」
  → generateWeeklyReport(force, monday)
    → 计算该周周一 ~ min(周日, 今天) 的日期
    → 逐天 loadDayFromAPI(date) 加载 records + chat（diaries 已加载）
    → 逐天 buildRawDiary(date) 拼原始日记
    → 拼接成一段文本（按天分隔）
    → callAiRaw(WEEKLY_PROMPT, 原始日记文本)
    → AI 返回「## 工作 … ## 生活 …」
    → 解析出 work / life 两段
    → 存 weeklyReports[周一日期] + 保存到后端
    → 显示在报告区
```

### 2. 周计算与选周

周一为一周开始：

```javascript
function getWeekStart(dateStr) { ... }   // 日期 → 所在周的周一
function getWeekEnd(monday) { ... }      // 周一 + 6 = 周日
function getWeeklyMonday() { return weeklyMonday || getWeekStart(todayStr()); }
```

全局状态 `weeklyMonday` 记录当前查看的周（null = 本周）。生成范围 = 该周周一 ~ `min(周日, 今天)`：历史周生成完整一周，未来天不生成。

切换周的入口：

| 入口 | 函数 | 行为 |
|------|------|------|
| 日期输入 + 「定位到该周」 | `locateWeekByDate()` | 取日期所在周为当前周 |
| 「◀ 上周」「下周 ▶」 | `shiftWeek(±1)` | 当前周 ± 7 天 |
| 「本周」 | `goThisWeek()` | 回到本周 |
| 下拉选历史周报 | `selectWeeklyReport(monday)` | 直接切到该周 |

### 3. AI 提示词

system prompt 固定要求输出两段：

```
你是我的周报助手。我会给你「本周每天的原始日记」，请总结成一份本周周报，严格按下面两部分输出：

## 工作
按天总结，每天一行，格式「周X：...」。哪天有内容就写，没内容跳过。要让我一眼看清每天做了什么；相关主题可合并到同一天，但每天核心事项要写清楚。

## 生活
先写一行「身体：共约 N 小时」，括号里列主要身体活动及估算时长（睡眠、吃饭、通勤、洗澡等）。
再写一行「精神：共约 N 小时」，括号里列精神领域活动及估算时长（看小说、刷视频等），并点明主要在做什么。

规则：
- 时间从原始日记里提取并估算，不要求精确
- 没内容的领域写「（无）」
- 语气自然，像朋友帮我复盘，不堆砌数字
```

message = 该周每天的原始日记，按天拼接，中间用空行分隔。

### 4. 存储

周报是「派生数据」（可从原始日记重新生成），存后端：

```javascript
let weeklyReports = {};   // { "周一日期": { work, life, generatedAt } }
// 后端 weekly_reports.json，端点：
//   GET/POST /api/weekly-reports        批量读写
//   POST /api/weekly-reports/:monday     写某周
```

登录用户走后端 `weekly_reports.json`；旧 localStorage（`qt_weekly_reports`）首次登录时自动迁移到后端，迁移完成打 `qt_weekly_reports_migrated` 标记。

## 三、数据模型

```javascript
weeklyReports = {
  "2026-08-10": {
    work: "周一：...\n周二：...",   // 「## 工作」段
    life: "身体：...\n精神：...",   // 「## 生活」段
    generatedAt: 1753000000000,     // 生成时间戳
  }
}
```

无。周报是消费端，不对外提供数据。

## 七、边界情况

1. 该周没有任何原始日记 → 提示「该周暂无数据」
2. 今天是周一 → 只有周一一天，照常生成
3. 选到未来周 → 无数据无周报，不显示「生成该周周报」按钮
4. 历史周无周报 → 显示「生成该周周报」，点击生成该周完整周报
5. 重复点「周报」→ 已有缓存直接显示，点「重新生成」才重新调 AI
6. AI 输出缺「## 工作」或「## 生活」→ 兜底处理，提示重试
7. 下拉「历史周报」只列已有周报的周；无任何周报时下拉只有占位项

## 八、修改注意事项

1. 周报存后端 `weekly_reports.json`（`/api/weekly-reports`），不再存 localStorage；清浏览器缓存不影响周报。旧 localStorage 数据首次登录自动迁移。
2. 全局 `weeklyMonday` 是「当前查看的周」，所有切换/生成都以它为准；null 表示本周。
3. `buildRawDiary` 依赖 `chatHistory`/`timelogs`/`diaries` 已加载，生成前必须先逐天 `loadDayFromAPI`。
4. 周报解析靠 `## 工作`/`## 生活` 字符串分隔，改 prompt 标题要同步改解析逻辑。
5. 「月报/季报/半年报/年报」仍走 `generatePeriodReport`，与周报互不影响。
