# 四象限任务

## 一、功能说明

四象限任务是左栏的工作规划系统。按 Eisenhower 矩阵管理任务优先级，支持拖拽排序和计时器联动。

核心功能：
1. **四象限**：Q1 紧急且重要 / Q2 重要不紧急 / Q3 紧急不重要 / Q4 不重要不紧急
2. **待办区**：未分配象限的任务暂放 todo 区
3. **拖拽入象限**：任务卡片可拖到任意象限，也可在同一象限内拖拽排序
4. **计时器联动**：点击任务 ▶ 开始计时 → 点击 ⏹ 停止 → 自动创建时间记录并关联（linkedTaskId）
5. **AI 补全**：计时器停止后 AI 自动补全该记录的 category/energy/flow
6. **快速添加**：输入框支持逗号分隔批量添加

## 二、技术原理

### 数据结构

```javascript
// tasks.json
{
  "tasks": [
    {
      "id": "t1785509039282",
      "name": "访谈纪要下载-存档-分析",
      "zone": "todo",           // "todo" | "urgent-important" | "noturgent-important" | ...
      "startAt": null,           // 计时中 → Unix ms，否则 null
      "elapsed": 0,              // 累计毫秒（暂停/完成时已加上已用时间）
      "running": false           // 是否正在计时
    }
  ],
  "done": []
}
```

### 四象限映射

| zone 值 | 颜色 | 标签 |
|---------|------|------|
| `urgent-important` | #E74C3C 红 | 紧急且重要 |
| `noturgent-important` | #27AE60 绿 | 重要不紧急 |
| `urgent-notimportant` | #F39C12 黄 | 紧急不重要 |
| `noturgent-notimportant` | #95A5A6 灰 | 不重要不紧急 |
| `todo` | — | 待办区 |

### 拖拽排序

```
dragstart → 记录 _dragId
  → dragover → dz.cardOver → 计算 drop 位置（上方/下方）
  → drop → dz.drop(zone)
    → 同象限内排序：插入到目标位置
    → 跨象限：移动到目标象限末尾
  → saveV3() → renderLeftCol()
```

拖拽同时支持：
- 从待办区拖入象限
- 象限间互拖
- 象限内排序（拖到某卡片上方/下方）

### 计时器联动

```
用户点击任务卡片 ▶
  → toggleTimer(id)
    → t.startAt = Date.now(), t.running = true
    → _activeTimers[id] = { taskName, startTime, startMs }
    → 启动 tick 每秒刷新 UI

用户再次点击 ⏹
  → toggleTimer(id)
    → t.elapsed += Date.now() - t.startAt
    → createRecord(currentDate, {
         linkedTaskId: t.id,
         start: _activeTimers[id].startTime,
         end: 当前时间,
         activity: t.name
       })
    → tryCallAIForComplete(record, t.name)  ← AI 补全评分
    → delete _activeTimers[id]
```

计时器停止后：
- 时间记录自动出现在中栏时间线（带 linkedTaskId）
- 时间线上该记录显示 🔗 图标
- AI 异步补全 category/energy/flow

### 任务完成与删除

完成：`completeTask(id)` → 从 tasks 移除，加入 done（当前 done 数组未在前端展示）。

删除：`deleteTask(id)` → 从 tasks 移除，不加入 done。如果正在计时 → 先停止计时。

### 数据持久化

任务数据走服务端存储（`GET/POST /api/tasks`），不再用 localStorage。
`saveV3()` → `apiCall('POST', '/api/tasks', {tasks, done})`。
`loadV3()` → `apiCall('GET', '/api/tasks')`。

## 四、跨模块关联

### 对外提供的数据

| 给谁 | 给什么 | 用途 |
|------|--------|------|
| 时间记录 | `linkedTaskId`（任务 id） | 计时器停止时创建记录并关联 |
| AI 评分 | `taskName` | `tryCallAIForComplete` 传入任务名用于 AI 分类 |
| 时间线渲染 | `_activeTimers` | 显示进行中的任务行 |

### 依赖的外部数据

| 来自谁 | 读什么 | 在哪用 |
|--------|--------|--------|
| 时间记录管理 | `createRecord()` | 计时器停止时创建记录 |
| AI 对话 | `POST /api/ai/raw` | tryCallAIForComplete |
| API key | profile.apiKey | AI 评分需要 key |

### 谁操作了任务数据

| 操作 | 触发 | 保存 |
|------|------|------|
| 添加任务 | 弹窗/快捷输入 | saveV3() → POST /api/tasks |
| 拖入象限 | 拖拽 drop | saveV3() |
| 象限内排序 | 拖拽 drop | saveV3() |
| 开始/停止计时 | toggleTimer | saveV3() + saveTimelogs() |
| 完成任务 | completeTask | saveV3() |
| 删除任务 | deleteTask | saveV3() |

## 五、修改注意事项

1. **linkedTaskId 是联动关键**：时间记录通过此字段关联到任务。如果改了任务 id 生成方式或删除任务的逻辑，需要注意已有记录的 linkedTaskId 不会自动清理（历史记录会指向已删除的任务 id）。

2. **计时器状态不跨 session 持久化**：`_activeTimers` 和 `startAt` 存在前端内存，刷新页面后计时器状态丢失。但 `elapsed` 已写入 tasks.json，所以已计入的时长不会丢。启动计时器时 `startAt = Date.now()`，停止时 `elapsed += Date.now() - startAt`。如果页面关闭时还有计时中的任务，下次打开后该任务不会自动恢复计时。

3. **zone 值不能随便改**：zone 字符串是四象限位置的标识，改了会导致历史任务从象限中消失（找不到匹配的 quadrant-cell data-zone）。

4. **tasks 数组和 done 数组分离**：完成的任务从 tasks 移到 done，但目前前端没有展示 done 列表。如果未来要加「已完成」视图，数据已经在 done 数组中。

5. **拖拽在两处使用同一套逻辑**：四象限和待办区共用 `dz` 对象，都响应 dragover/dragleave/drop 事件。新增拖拽目标时需同步加这三类事件。

6. **AI 对话可创建任务**：系统提示词已支持 `createTask` action，用户语音提待办会自动写入四象限。前端 `executeAction` 的 batch 循环和独立 case 均有处理。
