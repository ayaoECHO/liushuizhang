# 时间记录管理

## 一、功能说明

时间记录是中栏下半部分的时间线列表。以时间为轴展示一天的时段分布，支持手动增删改和拖拽合并。

核心功能：
1. **时间线展示**：按时间排序展示当天所有记录，跨天睡眠排最前，其余按 start 排序
2. **手动添加**：弹窗填写起止时间、活动名、分类、维度
3. **行内编辑**：点击时间、活动名直接修改
4. **质量分编辑**：点击 ♥️/🎯 弹出下拉菜单选 energy/flow 分数
5. **拖拽合并**：拖一条记录到另一条 → 合并为一条，时间取并集，标题取较长者
6. **撤销合并**：合并后可撤销，恢复原来的两条记录
7. **删除**：点击 ✕ 删除单条记录

## 二、技术原理

### 数据结构

```javascript
{
  id: "9s2x3s7y",                  // 唯一 id
  date: "2026-08-05",              // 所属日期
  start: "08:00",                  // HH:MM 格式
  end: "09:15",
  title: "通勤",                   // 活动名称
  category: "工作",                // 四分类之一
  duration: 75,                    // 分钟
  energy: 0,                       // -3 到 +3
  flow: 0,                         // -3 到 +3
  dimension: "commute",            // 六维度之一
  breakdown: [                     // 子活动拆分
    { activity: "通勤", duration: 75, dimension: "commute" }
  ],
  corrected: false,                // 用户手动改过
  linkedTaskId: "",                // 关联的四象限任务 id
  createdAt: 1785979403688,        // 创建时间戳
}
```

### 排序规则

```javascript
timelogs[date].sort((a, b) => {
  const aMain = isMainSleep(a), bMain = isMainSleep(b);
  if (aMain !== bMain) return aMain ? -1 : 1;  // 主睡眠排最前
  return (a.start || '').localeCompare(b.start || '');
});
```

主睡眠判断：`dimension === 'sleep' && start > end`（跨天，如 22:30-08:00）。

### 创建记录（createRecord）

`createRecord(dateStr, data)` → 从 data 生成完整 record 对象 → 推入 `timelogs[date]` → 排序。

关键处理：
- breakdown 各项 duration 之和 ≠ 总 duration → 按比例缩放修正（`scaleBreakdown`）
- 数据来自 AI 对话时，`data` 由 `executeAiAction` 传入
- 数据来自计时器时，`linkedTaskId` 填任务 id（`createRecord(currentDate, {..., linkedTaskId: t.id})`）

### 合并记录（拖拽）

```
timeline-row → dragstart → _tlDragId = id
  → dragover 检测 .timeline-row 并高亮 merge-target
  → drop → 深拷贝两条记录做快照（_lastMerge）
    → 合并：时间取并集（start 取早、end 取晚）
    → duration 相加
    → title 取较长者
    → 删除源记录
    → 刷新时间线
```

### 撤销合并

`undoMerge()` → 恢复 `_lastMerge` 的快照数据 → 还原 tgt 备份 → 重新插入 src 备份 → 重新排序。

`_lastMerge` 只在当前日期有效，切换日期后按钮置灰。

## 五、修改注意事项

1. **排序规则不改**：主睡眠排最前 + 其余按 start 排序。改变排序会影响 AI 上下文中记录的展示顺序。

2. **breakdown 缩放修正不能去掉**：`createRecord` 中 `scaleBreakdown` 是安全网，防止 AI 返回的 breakdown 时长之和不等于总 duration。

3. **datetime-local 显示格式**：`start`/`end` 在后端存为 `HH:MM` 字符串，手动添加弹窗用 `<input type="time">` 处理。

4. **合并快照只存一份**：`_lastMerge` 是单值变量，只能撤销最近一次合并。如果连续合并两条 → 第二次合并覆盖快照 → 只能撤销第二次。

5. **切换日期重置撤销**：`updateUndoBtn()` 在日期切换时调用，`_lastMerge.date !== currentDate` 则按钮置灰。

6. **服务端写文件是全量覆盖**：`POST /api/day/:date` 是整文件覆写，不是增量 patch。前端 `saveDayToAPI(date)` → `apiCall('POST', '/api/day/' + date, {records, deletedIds})` 需传完整的 records 数组（deletedIds 是待删除记录 id，服务端删除后置空）。
