# AI 对话记录

## 一、功能说明

AI 对话是时间记录的核心输入通道。用户在右栏用自然语言描述一天做了什么，AI 自动解析为结构化时间记录。

核心能力：
1. **批量创建记录**：一段话描述多个时段，AI 拆分为多条记录
2. **级联修改**：改某条记录的结束时间 → 后续记录的起始时间同步调整
3. **追问确认**：信息不完整时主动追问，用户回应后继续处理
4. **时间推断**：根据上下文自动判断 AM/PM、跨日期活动归属

## 二、技术原理

### 对话流程

```
用户输入文本
  → POST /api/chat { date, message }
    → 加载系统提示词 + 已有记录 + 聊天历史
    → 调 DeepSeek API（deepseek-v4-flash）
    → AI 返回 JSON（含 action + 数据 + reply 文本）
    → 前端根据 action 类型执行操作
    → AI 回复显示在对话区
```

### AI 返回格式

**批量操作**：
```json
{
  "action": "batch",
  "items": [
    {"action": "create", "data": {"date": "...", "start": "...", "end": "...", "title": "...", "category": "...", "dimension": "...", "breakdown": [...]}},
    {"action": "update", "id": "record_id", "data": {"end": "22:40"}},
    {"action": "delete", "id": "record_id"}
  ],
  "reply": "已记录上午的时段，下午干什么了？"
}
```

**单操作**：
```json
{"action": "create", "data": {...}, "reply": "..."}
{"action": "update", "id": "...", "data": {...}, "reply": "..."}
{"action": "ask", "reply": "下午具体在做什么？"}
```

### AI 支持的操作类型

| action | 作用 | 说明 |
|--------|------|------|
| `create` | 创建时间记录 | data 含 date/start/end/title/category/dimension/breakdown |
| `update` | 修改已有记录 | 必须带 id，data 只写要改的字段 |
| `delete` | 删除已有记录 | 必须带 id |
| `createTask` | 创建四象限任务 | data 含 name（任务名），zone 默认 "todo" |
| `ask` | 追问用户 | reply 必填，不操作数据 |

### 系统提示词核心规则

提示词定义在 `server.js` 的 `对话提示词` 常量中（约 150 行），核心规则：

1. **reply 与 JSON 必须一致**（最高优先级）
2. 不编造数据，用户没说的不脑补
3. update/delete 必须带 id
4. 级联调整：改 end → 后续记录的 start 同步调整
5. 活动名称精简
6. 吃饭相关归并，洗碗单独记录
7. 吃饭+洗碗同时提到 → 拆分两条，时间各半

### 日期推断

- 用户消息以"X月X日——"开头 → 该日期为基准
- 无前缀 → 默认系统日期
- 跨天活动自动推断实际日期（判断标准：时间是否衔接昨天的记录末尾）
- 夜间睡眠 date 填醒来当天，入睡时间自动推断（"昨晚10点"→22:00，"凌晨1点"→01:00）

### 幻觉校验

`POST /api/chat` 返回前会调用 `validateCreates()`：检查 AI 创建的活动标题是否在用户消息中至少出现 2 个连续字符。如果发现了用户没提到的活动 → 自动重试一次（把疑似幻觉发给 AI 要求重新生成）。

### 追问停止规则

用户回应追问时表达了「当前给不了答案」→ 停止追问。停止信号包括：「进行中」「一会说」「等下」「还没弄完」「醒了告诉你」「不记得了」。

## 五、修改注意事项

1. **新增 action 类型**：需同步改三处——系统提示词（输出格式 + 示例）、前端的 batch 循环、前端的独立 case。`createTask` 是最近加上的，可作为参考模板。

2. **reply 与 JSON 一致性规则不可弱化**：这是提示词的第一优先级规则，弱化会导致 AI 说一套做一套（嘴上说"已记录"但 JSON 为空）。

3. **幻觉校验不能去掉**：`validateCreates()` 是防止 AI 编造活动的最后防线。如果新增 action 类型需要在校验逻辑中对应处理。

4. **追问停止规则的优先级**：仅次于规则 1。改动了追问逻辑要确保不出现「用户说等下，AI 继续追问」的循环。

5. **分类体系不要随意扩充**：四分类是用户确认过的，改变会影响所有历史记录的统计和筛选。

6. **不能直接给 AI 传 linkedTaskId**：当前 AI 上下文中传了 `recordsText` 包含 linkedTaskId（line 401），但 AI 创建记录时没有传 linkedTaskId 的字段。如果未来要做 AI 自动关联任务，需要在 create action 的 data 中增加 linkedTaskId 字段定义。

7. **token 消耗**：系统提示词约 150 行 + 已有记录文本 + 聊天历史，估算每次调用约 2000-4000 input tokens。修改提示词时注意控制长度。
